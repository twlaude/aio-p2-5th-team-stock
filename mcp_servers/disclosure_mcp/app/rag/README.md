# Disclosure RAG

사업보고서 전체를 LLM에 전달하지 않고, 질문에 관련된 공식 원문 구절만 찾아 반환한다.

## 처리 흐름

```text
사업보고서 원문(XML)
  → 본문·표·목차 정리
  → 의미 단위 청킹
  → 임베딩 생성
  → pgvector 저장
  → 기업·문서 종류·최신 접수번호 선필터
  → 질문 벡터 검색
  → 관련 구절과 출처 반환
```

## 저장 단위

각 청크는 최소한 기업명, 종목코드, `corp_code`, 보고서명, 사업연도, 접수번호, 발행일, 섹션명, 원문 텍스트, 임베딩, 수집 시각을 가진다. 원문 위치를 유지해 사용자에게 공시뷰어 URL을 제공할 수 있어야 한다.

## 검색 규칙

- `company_name` 또는 `stock_code`로 회사를 먼저 확정한다.
- 최신 사업보고서의 청크만 기본 검색 대상이다.
- `top_k`는 1~5이며, 유사도 기준을 넘지 못하면 억지로 근거를 반환하지 않는다.
- 반환 문단은 원문이며, 요약은 Tool 밖의 LLM이 근거 문단을 바탕으로 수행한다.

## 수집 범위

전 기업 원문을 일괄 색인하지 않는다. 요청된 기업의 최신 사업보고서를 온디맨드로 수집·색인하고, 이후 질의에는 저장된 결과를 재사용한다.
