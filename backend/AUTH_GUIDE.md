# 로그인과 Mock 사용자 가이드

## 왜 Mock 단계에도 사용자 구분이 필요한가

투자 성향과 Memory는 사용자마다 다르다. 따라서 실제 회원가입을 만들지 않더라도 현재 요청이 어느 데모 사용자의 것인지 구분해야 한다.

## 1단계: 데모 인증

```text
사용자 A
├─ 투자 성향: 안정형
├─ 투자 기간: 장기
└─ 투자 경험: 초보

사용자 B
├─ 투자 성향: 공격형
├─ 투자 기간: 단기
└─ 투자 경험: 경험 있음
```

Frontend에서 데모 사용자를 선택하고 Backend 요청 헤더에 교육용 사용자 식별자를 보낸다. 이 방식은 로컬 데모에서만 사용한다.

## 2단계: 실제 인증

- 회원가입
- 비밀번호 해시 저장
- 로그인
- Access Token 발급
- 인증된 토큰에서 사용자 ID 확인

요청 본문에 들어 있는 `user_id`를 그대로 신뢰하지 않는다.

## 로그인 후 화면 분기

```text
로그인 성공
  → 투자 성향 조회
     ├─ 있음: FE1 종목 검색
     └─ 없음: FE0-2 투자 성향 설정
```

사용자가 먼저 종목을 검색한 뒤 투자 성향 설정이 필요해진 경우, 검색한 종목은 Redis 단기 상태 또는 Frontend 세션에 보관하여 설정 완료 후 분석을 이어간다.

## 저장하면 안 되는 정보

- 원문 비밀번호
- 카드·계좌 비밀번호
- 주민등록번호
- API Key
- Access Token
- Refresh Token 원문

## 발표에서 보여줄 수 있는 장면

같은 삼성전자를 검색하더라도 공통 분석은 같고, 사용자 A와 B의 `나를 위한 확인 포인트`만 달라지는 모습을 보여준다.
