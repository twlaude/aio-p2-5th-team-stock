# Frontend 화면 흐름

화면 시안은 `docs/assets/이미지/`에 있다. 이미지는 최종 디자인이 아니라 배치 참고 자료다.

## 1. 확정 사용자 흐름

```text
종목 검색
  → 지원 종목 확인
  → 기업명·현재 가격·등락·공통 한 줄 설명
  → 왜 이렇게 판단했나요?
      ├─ 비회원: 회원가입이 필요합니다!
      └─ 회원: 시장 온도·근거·개인화 확인 포인트
```

로그인하지 않아도 검색과 공통 결과를 볼 수 있다. 투자 성향은 회원 상세 결과를 만들 때만 사용한다.

## 2. 검색 화면

참고 이미지: `docs/assets/이미지/01.png`

- 서비스명 `살래? 말래?`
- 기업명 또는 6자리 종목 코드 검색
- 지원 기업 20개 안내
- 로그인 버튼 또는 현재 Mock 사용자
- 검색 결과가 없는 경우와 미지원 기업을 구분

`많이 검색한 종목`은 실제 집계가 준비되지 않으면 고정 Mock으로 표시하거나 제외한다.

## 3. 공개 결과 영역

참고 이미지: `docs/assets/이미지/03.png`

비회원과 회원에게 공통으로 표시한다.

- 기업명·종목 코드
- 현재 가격
- 가격 변화와 등락률
- 데이터 기준 시각
- 추천 표현이 없는 공통 한 줄 설명

비회원에게 뉴스·보고서·커뮤니티 상세나 투자 성향 결과를 노출하지 않는다.

## 4. 로그인과 Mock 사용자

참고 이미지: `docs/assets/이미지/02.png`

- Mock 사용자 10명 중 하나로 로그인
- 사용자별 투자 경험, 위험 성향, 투자 기간, 선호 근거가 미리 준비됨
- 상세 버튼을 누른 상태에서 로그인하면 원래 종목의 상세 결과로 돌아감
- 실제 회원가입은 발표 필수 범위가 아님

## 5. 회원 상세 영역

참고 이미지: `docs/assets/이미지/04.png`

한 결과 페이지에서 아래로 스크롤하는 방식으로 구현한다.

1. 시장 온도와 라벨
2. 시장 온도를 만든 데이터 범위
3. 뉴스 요약과 출처
4. 기업보고서·공시 요약과 출처
5. 커뮤니티 반응·표본 수·공포탐욕 지수
6. 가격 기준 시각
7. 사용자의 투자 성향에 맞춘 확인 포인트
8. 데이터 부족과 부분 실패 안내

## 6. Frontend 연결 원칙

- Backend의 `/api/v1`만 호출한다.
- MCP 서버, MCP Client, PostgreSQL, Redis를 직접 호출하지 않는다.
- `access_level`과 `requires_login`으로 공개·회원 영역을 구분한다.
- 가격·출처·수집 시각을 Mock 값과 혼동하지 않게 표시한다.
- 시장 온도가 상승 가능성이나 매수 점수로 보이지 않도록 안내 문구를 둔다.

세부 JSON은 `shared/contracts/frontend_backend/README.md`를 따른다.

## 7. 제외 화면

관리자 페이지, 실제 주문, 포트폴리오, 종목별 사용자 게시판은 이번 Frontend 범위가 아니다.
