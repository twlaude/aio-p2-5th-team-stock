# Frontend 화면 흐름

> **한눈에**
> 검색·공통 결과는 비회원도 봅니다.
> 회원은 근거·성향별 확인 포인트를 봅니다.
> 상세는 한 페이지에서 스크롤합니다.

최종 화면 기준은 `frontend/tests/shots/`의 실제 스크린샷입니다.

## 1. 확정 사용자 흐름

```text
종목 검색
  → 지원 종목 확인
  → 기업명·현재 가격·등락·공통 한 줄 설명
  → 왜 이렇게 판단했나요?
      ├─ 비회원: 회원가입이 필요합니다!
      └─ 회원: 시장 온도·근거·개인화 확인 포인트
```

투자 성향은 회원 상세 결과에만 사용합니다.

## 2. 검색 화면

- `살래? 말래?`: 기업명·6자리 코드 검색, 지원 기업 20개 안내.
- 로그인 버튼 또는 현재 Mock(예시) 사용자 표시. 결과 없음·미지원은 구분합니다.

`많이 검색한 종목`은 실제 집계 전까지 고정 Mock으로 표시하거나 제외합니다.

## 3. 공개 결과 영역

회원·비회원 공통: 기업명·코드, 현재 가격·변화·등락률, 기준 시각, 추천 없는 한 줄 설명.
비회원에게 뉴스·보고서·커뮤니티 상세와 투자 성향 결과는 숨깁니다.

## 4. 로그인과 Mock 사용자

Mock 사용자 10명 중 하나로 로그인합니다. 투자 경험·위험 성향·기간·선호 근거는 사전 설정입니다.
상세 버튼에서 로그인하면 원래 종목 상세로 돌아갑니다. 실제 회원가입은 발표 필수가 아닙니다.

## 5. 회원 상세 영역

시장 온도·라벨 → 산정 데이터 범위 → 뉴스 요약·출처 → 기업보고서·공시 요약·출처 → 커뮤니티 반응·표본 수·공포탐욕 지수 → 가격 기준 시각 → 성향별 확인 포인트 → 데이터 부족·부분 실패 안내.

## 6. Frontend 연결 원칙

- Backend `/api/v1`만 호출합니다. MCP 서버·MCP Client·PostgreSQL·Redis 직접 호출은 금지합니다.
- `access_level`·`requires_login`으로 공개·회원 영역을 구분합니다. 가격·출처·수집 시각은 Mock과 구별합니다.
- 시장 온도는 상승 가능성·매수 점수가 아님을 안내합니다.

JSON은 `docs/specs/contracts/frontend_backend.md`를 따릅니다.

## 7. 제외 화면

관리자 페이지·실제 주문·포트폴리오·종목별 사용자 게시판은 제외합니다.
