# 전체 테스트 가이드

## 목적

각 팀원이 만든 서버가 독립적으로 동작하는지와 마지막에 전체 흐름이 연결되는지를 확인한다.

## 테스트 단계

### 1. 각 서버 단독 테스트

- 뉴스 MCP가 Mock 뉴스 응답을 반환하는가
- 전자공시 MCP가 Mock 공시 응답을 반환하는가
- 커뮤니티 MCP가 Mock 반응을 반환하는가
- MCP Client가 각 서버 실패를 구분하는가
- Backend가 사용자별 Memory를 구분하는가
- Frontend가 Backend 오류를 표시하는가

### 2. 계약 테스트

- 실제 응답 필드가 `shared` 계약과 일치하는가
- 날짜 형식이 동일한가
- 출처 URL과 수집 시각이 존재하는가
- 결과 없음과 서버 오류가 구분되는가

### 3. 전체 흐름 테스트

```text
데모 사용자 로그인
  → 투자 성향 확인
  → 삼성전자 검색
  → Backend
  → MCP Client
  → 네 MCP 서버
  → 공통 분석
  → 개인화 확인 포인트
  → FE2 표시
```

### 4. 사용자 분리 테스트

같은 삼성전자를 검색한다.

- 사용자 A와 B의 공통 분석은 같은가
- 개인화 확인 포인트만 다른가
- 사용자 A의 Memory가 사용자 B에게 노출되지 않는가

### 5. 장애 테스트

- 뉴스 MCP만 중단
- 전자공시 결과 없음
- 커뮤니티 원본 서버 타임아웃
- Redis 재시작
- LLM 응답 실패

일부 데이터가 없을 때 사실을 만들어 내지 않고 제한 상태를 보여줘야 한다.

## 첫 번째 통합 완료 기준

실제 API 대신 Mock Data를 사용해도 다음 왕복이 성공하면 첫 통합이 완료된 것으로 본다.

```text
Frontend → Backend → MCP Client → MCP 서버 → Backend → Frontend
```

그다음 각 Mock 응답을 실제 데이터 연결로 하나씩 교체한다.
