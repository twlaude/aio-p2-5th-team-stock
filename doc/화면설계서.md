# 화면 설계서

프론트엔드는 **React 단일 페이지 앱**입니다. 홈에서 종목 검색부터 공개 결과, 회원 근거, 개인화 확인 포인트까지 아래로 이어서 보여 주고, 로그인만 별도 경로로 분리합니다.

| 구분 | 대상 | 경로 | 핵심 역할 |
|---|---|---|---|
| 홈 단일 페이지 | 비회원·회원 공통 | `/` | 검색, 공개 결과, 게스트 게이트, 회원 근거, 개인화 결과를 한 흐름으로 표시 |
| 데모 로그인 | 비회원·회원 전환 | `/login` | 투자 성향이 준비된 데모 계정 10개 중 하나를 선택해 로그인 |
| 지원 기업 시트 | 비회원·회원 공통 | `/` 위 모달 | 2026년 9월 1일 기준 KOSPI 시가총액 상위 지원 기업 20개 탐색 |

Frontend는 Backend의 `/api/v1`만 호출합니다. MCP Client, MCP 서버, PostgreSQL, Redis를 브라우저에서 직접 호출하지 않습니다.

## 1. 한 페이지로 구성한 이유

사용자는 종목을 검색한 뒤 가격, 판단 문장, 근거를 한 번에 이해해야 합니다. 화면을 여러 페이지로 나누면 앞에서 본 가격과 뒤에서 본 뉴스·공시를 머릿속에서 다시 연결해야 하므로, 홈을 **위에서 아래로 읽는 하나의 분석 이야기**로 구성했습니다.

- 첫 화면에서는 검색만 강조하고, 분석이 시작되면 히어로 높이를 줄여 결과까지의 거리를 짧게 만듭니다.
- 가격과 한줄결론은 로그인 여부와 무관하게 공개합니다. 서비스가 무엇을 제공하는지 확인한 뒤 로그인 여부를 결정할 수 있습니다.
- 상세 근거는 `access_level`이 `member`인 응답에서만 렌더합니다. 비회원 응답은 `detail: null`, `personalized_checkpoints: null`이므로 화면에서 숨기는 수준이 아니라 응답 계약부터 분리됩니다.
- 로그인은 `/login`으로 이동하지만 보던 검색어를 `localStorage`에 저장합니다. 로그인 성공 후 `/`로 돌아오면 같은 종목을 회원 토큰으로 자동 재분석합니다.
- 회원 근거 영역의 sticky 탭은 새 페이지를 여는 메뉴가 아니라 현재 페이지의 네 근거 섹션으로 스크롤하는 목차입니다.

## 5. 검색과 공개 결과의 상태 설계

**검색 히어로와 마스코트.** 마스코트는 `idle`, typing, submit, thinking, oops 상태로 검색 진행을 보조합니다. 제출 후 히어로를 압축하되 검색창은 남깁니다. 삼성전자·SK하이닉스·현대차·셀트리온 칩은 실시간 인기 통계가 아닌 화면 상수입니다.

**가격 헤더와 스파크라인.** 종목·현재가·등락·서울 기준 시각을 숫자 부호와 색으로 표시합니다. 스파크라인은 `stock_code` seed와 `change_rate` 방향으로 생성한 **장식용 추세선**이며 실제 시계열 연결은 **후순위**입니다.

**한줄결론과 앰비언트 키워드.** 추천 지시 없이 가격·뉴스·공시·커뮤니티를 연결하고, 회원 재료줄에는 `sources` 기반 건수를 표시합니다. 회원 키워드는 community 집계 주제이며 데스크톱 최대 12개·모바일 최대 4개입니다. 비회원 `topics_preview`는 **mock 전용 계약 외 필드**여서 live 응답에 없으면 표시하지 않습니다.

## 6. 회원 게이트와 로그인 복귀

| 순서 | 저장·판정 기준 | 화면 동작 |
|---|---|---|
| 1 | 분석 응답의 `access_level` 확인 | `guest`이면 공개 결과만, `member`이면 근거·개인화를 렌더합니다 |
| 2 | 비회원이 Why 버튼 선택 | 실제 근거 대신 blur 미리보기와 로그인 안내 카드를 펼칩니다 |
| 3 | Mock 계정 로그인 선택 | 현재 검색어를 `sallae.search.pendingQuery`에 저장하고 `/login`으로 이동합니다 |
| 4 | 데모 사용자 선택·로그인 | 공통 비밀번호로 로그인하고, 프로필 조회는 실패해도 로그인 자체는 유지합니다 |
| 5 | `/` 복귀 | 토큰 변경을 감지해 보류 검색어를 회원 요청으로 자동 재분석합니다 |
| 6 | 회원이 Why 버튼 선택 | `#evidence`로 부드럽게 스크롤합니다 |

화면 문구는 "회원가입이 필요합니다!"이지만 현재 버튼의 실제 행동은 **Mock 계정 로그인**입니다. 실제 회원가입 화면은 이번 발표 범위에 구현되어 있지 않으며 **후순위**입니다.

## 7. 근거와 개인화 화면

### 7.1 요약 게이지

첫 번째 카드는 `market_temperature.score`를 0~100으로 제한해 시장 관심 온도로 보여 줍니다. 커뮤니티 데이터가 포함되면 커뮤니티 언급량·뉴스 기사량·거래량 변화 기준이라고 설명하고, 커뮤니티가 빠졌다면 뉴스·거래량 기준이라고 명시합니다. 온도는 상승 가능성이나 매수 점수가 아니라는 문구를 함께 둡니다.

두 번째 카드는 `evidence_level.level`을 낮음="아직 조금", 중간="절반쯤", 높음="많이 확인됨"의 3단계로 바꿔 보여 줍니다. 수치 정밀도를 과장하지 않고 공시·보고서로 확인된 정도를 빠르게 읽도록 설계했습니다.

### 7.2 분위기 vs 근거

시장 관심 온도와 공시 확인 단계를 조합해 `온도차 큼`, `온도차 있음`, `비슷함`, `조용한 편`으로 구분합니다. 뉴스 집중, 비슷한 기사 재게재, 공식 확인 항목, 커뮤니티 긍정 비율, 당일 가격 변화를 보조 신호로 표시합니다. 이 판정은 현재 Frontend의 표시용 휴리스틱이며 Backend/MCP Client 계약의 독립 필드가 아닙니다.

### 7.3 근거 섹션과 sticky 탭

탭은 분위기 vs 근거, 커뮤니티 반응, 최신 뉴스, 기업보고서·공시 순서입니다. 스크롤 위치를 `IntersectionObserver`로 감지해 현재 탭을 강조하고, 탭을 누르면 해당 섹션으로 이동합니다. 내비게이션 높이를 측정해 sticky 탭과 섹션 제목이 겹치지 않게 offset을 계산합니다.

각 섹션은 요약과 출처를 함께 보여 줍니다. 뉴스는 원문 링크와 재게재 횟수, 공시는 접수번호와 확인/미확인 내용을 구분합니다. 커뮤니티는 표본·비율·FGI·집계 주제를 보여 주되 "사실이 아닌 시장 반응"이라고 명시합니다.

### 7.4 개인화 카드

개인화는 공통 근거를 바꾸는 기능이 아니라 사용자가 먼저 확인할 순서를 바꾸는 기능입니다. 로그인 세션의 위험 성향·투자 기간·경험 수준을 라벨로 보여 주고, `personal_summary`의 첫 문장을 크게, 나머지 문장을 부연으로 표시합니다. `priority_checks`는 최대 3개만 번호 카드로 보여 주며 `caution`을 마지막에 분리합니다.

`profile_completed: false`이면 "성향 설정이 필요해요"만 표시합니다. 성향 등록·수정 폼은 현재 없으며 **후순위**입니다.

## 8. 오류와 부분 실패

| 상태 | 판정 | 유지하는 내용 | 사용자가 할 수 있는 일 |
|---|---|---|---|
| 미지원 | `status: "unsupported_company"` | 검색창과 지원 기업 20개 목록 | 지원 기업을 선택해 다시 분석 |
| 전체 실패 | 분석 요청 예외 | 입력한 검색어 | "다시 시도"로 같은 분석 재호출 |
| 기업 목록 실패 | 지원 기업 API 예외 | 검색창과 인기 기업 칩 | 오류를 닫고 검색어 직접 입력 |
| 부분 실패 | Backend `partial_success` 또는 개별 summary·coverage 누락 | 가격, 한줄결론, 성공한 근거, 개인화 | 실패 섹션의 "다시 시도"로 전체 분석 재호출 |

부분 실패는 전체 분석을 빈 화면으로 만들지 않습니다. 예를 들어 커뮤니티가 빠지면 관심 온도 설명에서 커뮤니티를 제외하고, 커뮤니티 카드에 제외 이유를 표시하며 뉴스·공시·가격은 계속 보여 줍니다.

## 10. 설계 포인트

- **추천 대신 확인 순서를 제공합니다.** "살래? 말래?"라는 이름과 달리 화면은 매수·매도 결론을 내리지 않습니다. 시장 관심 온도, 공식 확인 정도, 출처, 개인별 우선 확인 항목으로 사용자의 검토를 돕습니다.
- **공개 가치와 회원 가치를 분리합니다.** 회사명·현재가·등락·공통 한줄결론은 공개하고, 원문 근거와 투자 성향 기반 확인 포인트는 회원 응답에서만 제공합니다.
- **분위기와 사실을 같은 점수로 섞지 않습니다.** 커뮤니티 반응은 긍정·중립·부정과 FGI로 보여 주되 사실이 아니라고 고지하고, 공시는 확인된 것과 아직 확인 안 된 것을 나눕니다.
- **부분 실패를 숨기지 않습니다.** 누락한 데이터와 그 영향을 직접 설명하고 성공한 데이터는 유지합니다. 사용자는 결과 전체가 완전한지 추측할 필요가 없습니다.
- **출처를 요약 옆에 둡니다.** 뉴스·공시 요약 아래에 원문 링크, 발행처 또는 접수번호, 시각을 배치해 AI 문장과 원자료를 오갈 수 있습니다.
- **동일 화면에서 맥락을 보존합니다.** 검색 결과와 근거가 같은 `/`에 있어 가격·판단·근거를 위아래로 비교할 수 있고, 로그인 뒤에도 보던 종목을 잃지 않습니다.
- **데모와 실데이터를 구분합니다.** 상단에 "Mock 데이터 · 실제 투자 정보 아님"을 표시합니다. 비회원 키워드 preview와 장식용 스파크라인도 실데이터처럼 서술하지 않습니다.
- **모션은 상태 피드백에만 사용합니다.** 마스코트·게이지·카드 등장은 분석 진행과 정보 계층을 설명하며, OS 모션 감소 설정을 존중합니다.
